# Goal

Give `col_edit()` the same summarization `row_edit()` already has: columns whose changed-row sets are identical collapse into one line that names the columns once and states the shared shape of the change — how many rows, how many cells — instead of one near-identical line per column. The model gains the changed-row set underlying each column edit, the printed lines keep their read-back-as-hint property, and the UI exposes the same groups at the same granularity as the CLI.

# Scope

`src/model.rs` (the `ColumnEdit` field and its documentation), `src/summary.rs` (`SummaryColumn` carries the row set), `src/lib.rs` (both construction sites), `src/human.rs` (grouping in `write_human`), `src/hint.rs` (the list-names grammar for Edit), `design.md` (line-format and summary wording), `demo/README.md` plus possibly `examples/generate_demo.rs` and a new fixture pair, `ui/server` (column grouping DTO and column-view filter), and the UI frontend (sidebar sub-entries and filtered column view). Deferred: any change to which events the summary chooses — the minimum-cover optimization, forcing, and coalescing are untouched, and a cell covered by a column edit today is covered by the same edit after this step; any grouping of the *cell* view; any change to `row_edit()` itself.

# Design

The central invariants are preserved. Determinism: the grouping key is the changed-row set, a cover-independent fact derived from the complete cell-level diff — the same evidence that already backs `changes`, which remains the set's length — so repeated runs are byte-identical and no tied-cover choice can leak into the output. No inferred event without evidence: the grouping asserts nothing new; it states existing per-column edits jointly, and every number on the grouped line is checkable against the data (each named column differs in exactly the stated rows). The complete cell-level diff is untouched.

The one genuine grammar change is the hint round-trip. design.md's rule is that a printed line reads back as the hint it looks like, with the claim first and detail fields after. Grouped column lines lead with several names, so the rule's "a bare word in that position reads as a name" must extend — for `col_edit` only — to several names, each an equal claim. This is a widening of the Edit grammar alone: every line the format could print before still parses with the same meaning, and every newly printable line parses too. Refusals stay refusals elsewhere: lists for rename/add/drop, and mixed single/rename forms within one edit line.

The type/value split is what makes the grouping clean. An earlier draft of this step constrained group membership by identical type aspect as well as row set, because a single line states `type:` once; the owner instead split the aspects into two lines, so the value grouping needs no type constraint at all and the type lines group on their own natural key, the type pair. The alternative that was rejected — per-column type detail inside a value group — would have broken the every-argument-after-the-first-is-a-field shape.

# Definition of done

`ColumnEdit` carries its changed-row set in the model and both construction sites populate it; the human format prints a column edit's type and value aspects as separate lines, value lines grouped one per changed-row-set and type lines one per type pair, singletons unchanged in shape; grouped lines parse back as Edit hints attaching to each named column while all other hint refusals hold; design.md's format and summary sections describe the grouping; the UI sidebar lists column groups and the column view filters to a selected group, with CLI and UI counts in agreement by construction; the demo README transcripts are regenerated with prose checked, and a fixture exercises the grouped line; and the full acceptance pass is clean with byte-identical repeated runs.
