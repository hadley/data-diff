# Goal

Reconciliation has three stages whose worst case is not linear in the input, all long anticipated by `design.md` in future tense: approximate rename inference measures every dropped column against every added one, swap inference measures every pair of rewritten same-name identities, and edit summarization runs an unbounded maximum matching — each of the first two also linear in matched rows per measurement, with no bound on either factor. This step makes the whole pipeline predictably bounded, as the design's own principles require, by benchmarking it and introducing deterministic sampling, counted computation budgets, valid partial results, and incomplete-stage reporting.

The governing idea is that a budget should ideally change *when* the answer arrives, not *what* the answer is, as far as that is possible — so the bounded searches are ordered by heuristics that reach the likely answers first, and exhaustion strands only the unlikely remainder. The central heuristic is positional: a renamed column usually keeps its position, so the exact stage examines the rank-aligned diagonal of drops against adds before anything else, and a table where every column was renamed in place — the commonest bulk rename there is — resolves in O(columns) pair examinations. Behind it, exact candidate discovery becomes a digest join rather than a pairwise scan, so no part of the stage is quadratic except the budgeted verification of genuinely identical-looking candidates. Where a budget does bind, every stage still returns a valid result: unexamined rename candidates stay drops and additions, an unfinished swap enumeration accepts nothing, and a summary too large for the exact solve returns a simpler cover that still covers every cell with `optimal: false` — and the diff says which stages were cut short, so a reader never mistakes a truncated search for a completed one.

## What stays and why

- **The complete cell-level diff.** Cell comparison is linear in identities times matched rows and is never sampled or budgeted: retaining the complete change set is a central invariant of `design.md`, and everything summarization truncates remains recoverable from it.
- **Every inference rule and threshold.** Agreement, kappa, informativeness, mutual uniqueness, the swap bars — budgets and samples change which pairs are examined and over which rows, never what examined evidence means. Sampling makes the agreement statistics estimates on very large tables, which the design accepted when it specified the sample; the thresholds are unchanged.
- **Key resolution, guessing, matching, ordering, and reconsideration.** All linear or linearithmic in the input, none bounded here. Reconsideration's second pass runs under fresh counters, so a bounded first pass cannot starve it.
- **Exact rename inference's full-row basis.** `Exact` means every matched row agreed; the pre-pass and the budget change how many pairs are examined, not what exactness asserts.
- **Determinism.** Budgets are counted in work units — pairs examined, rows sampled, changed cells admitted to the exact cover — never wall-clock time, so repeated runs remain byte-identical, budgets binding or not.

## Explicitly deferred

- **CLI and UI exposure of budgets.** The `Budgets` struct is the library mechanism; flag syntax, interactive overrides, and progress reporting stay deferred with the other UI decisions in the queue's closing note.
- **Bounding key guessing and uniqueness checks.** Linear scans per candidate column; the benchmarks will show whether wide tables ever make them hurt, and a bound rides on that evidence rather than ahead of it.
- **A demo section for incompleteness.** Needs a fixture big enough to bind a default budget, which does not belong in the repository; the injectable budgets cover the behavior in tests.

# Design

## Budgets are counted, never timed

The design requires predictably bounded computation and byte-identical repeated runs at once, and a timed budget cannot serve both: what a millisecond buys depends on the machine. Every budget is therefore a count of deterministic quantities — rows sampled, first-time pair measurements for the inference stages, changed cells admitted to the exact cover — consumed in a deterministic order, so the set of examinations that fit under a budget is a pure function of the input and options. "Elapsed work" in the existing design text becomes exactly this.

## Heuristics order the search so exhaustion strands only the unlikely

A bounded search is only as good as what it examines first. Renames usually preserve a column's position among its peers, so the diagonal of rank-aligned drop/add pairs is verified before anything else, and each exact hit removes both endpoints from every later candidate structure — the bulk-rename case resolves before the general machinery runs at all. The pre-pass claims only informative exact pairs: position is good evidence for choosing *among* real matches, which is why the informative tie-break now prefers it, but it is not evidence that indistinguishable constant columns correspond, so the recorded refusal of competing constants is preserved rather than overridden by position. After the diagonal, examination proceeds in the established column order, which keeps partial acceptance deterministic and leaves the least-likely pairs — far-flung, low-agreement candidates — to be the ones a budget strands.

## Partial results must be valid, and each stage has its own notion of valid

Rename inference's unit of sound acceptance is the endpoint group — a pair is accepted only after every candidate incident to both endpoints has been examined, as the design already requires — so exhaustion strands whole endpoints, which simply remain drops and additions: the report is conservative, never wrong. Swap inference's cancellation rule is global — any unexamined candidate could have canceled an accepted swap — so its only sound partial result is no swaps at all, and the same-name identities stand as they would if no swap had been found. Summarization's contract is that every changed cell is covered, which each component's smaller affected side satisfies without any solving at all; `optimal: false` plus `incomplete_summary()` say the description may be redundant, never that it is incomplete as evidence — the full cell set is untouched underneath. And a large summary is deliberately not a regeneration: `table_regenerate()` claims the matching is not credible, which the diff's size alone cannot establish — the change-mass rule remains its only trigger, and the declined size- and column-share triggers are recorded in `design.md` with their counterexamples.

## The sample is a function of the key

The sampled rows must be the same on every run and must not depend on incidental row order more than the input itself does, so the sample is chosen by hashing each matched pair's canonicalized key values and keeping the smallest `agreement_rows` digests, ties broken by old position. Hashing the key rather than the position means the same logical rows are sampled across the two passes of reconsideration when the key survives, and the xxh3 the codebase already depends on serves unchanged. Exact inference never samples: its basis is a universal claim, and the linear full-column digest pass it rests on is exactly the cost the design accepts for it.

# Definition of done

This step is complete when:

- every piece of row-touching work in reconciliation is either counted against a budget or part of a pass whose cost is linear in the input, up to a matrix-bounded constant, and recorded as such in `design.md`'s costs note — with the remaining column-shaped work (the digest join, the ordering analyses) likewise recorded with its cost;
- a table where every column is renamed in place resolves through the positional pre-pass in O(columns) pair examinations, demonstrated by a benchmark scenario and pinned by a test;
- approximate rename and swap inference measure over the deterministic key-hash sample above `agreement_rows` matched rows, with exact inference untouched;
- exhaustion of each budget yields the stage's stated valid partial result, reported through `Diff::incomplete` and the `incomplete_*()` problem lines, and default budgets leave every existing test, snapshot, and demo transcript byte-identical;
- repeated runs are byte-identical on every path, budgets binding or not;
- the benchmark harness exists, runs, and is the recorded basis for the chosen constants; and
- the full test suite, strict Clippy, formatting, and diff checks pass across the workspace.
