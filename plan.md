# Goal

The opaque step admitted dates, timestamps, and decimals but compared each only against its identical source type, so the commonest real retypes — a timestamp column moved from milliseconds to nanoseconds, a date widened to `Date64`, a decimal's precision raised, a decimal column against the integer or double column it replaced — read as type-only edits with their values never compared. Each of those pairs is the same values retyped, and each has an exact, decidable equality. This step gives each listed pair its decided rule in the comparison matrix, replacing incomparability with semantics, and closes [#1 (decimal support)](https://github.com/hadley/data-diff/issues/1) and [#2 (temporal support)](https://github.com/hadley/data-diff/issues/2) — the owner has judged the categories left identical-type-only (local times, durations, intervals) out of what closing them requires:

| Pair | Rule |
|---|---|
| aware timestamp ↔ aware timestamp | Equal instants, exactly, across units and timezone strings |
| naive timestamp ↔ naive timestamp | Equal wall-clock readings, exactly, across units |
| `Date32` ↔ `Date64` | Equal values; a non-midnight `Date64` equals no `Date32` |
| date ↔ naive timestamp | Equal when the timestamp is exactly the midnight beginning the date's day |
| decimal ↔ decimal | Equal values, exactly, across precision, scale, and 128/256 width |
| decimal ↔ `int64` | Equal when the decimal is exactly that integer |
| decimal ↔ `double` | Equal when the two exact values coincide, never through lossy conversion |
| `string` ↔ date | Parse the ISO 8601 calendar date `YYYY-MM-DD`, then compare exactly |
| `string` ↔ naive timestamp | Parse the ISO 8601 unzoned date-time `YYYY-MM-DDTHH:MM:SS[.f…]`, then compare exactly |
| `string` ↔ aware timestamp | Parse the ISO 8601 instant — the same date-time with a required `Z` or `±HH:MM` offset — normalized to UTC, then compare exactly |
| `string` ↔ decimal | Parse the exact numeric grammar to a rational, then compare exactly |

The string rows follow the matrix's recorded principle that each string domain parses by its partner column's spelling rules, with one explicitly selected ISO 8601 profile per partner category — which is exactly the shape [#2](https://github.com/hadley/data-diff/issues/2) asks for, and what dissolves the objection that a date has no one spelling: the profile chooses it.

Equally deliberate are the refusals, following the queue's discipline that a pair with no defensible rule stays incomparable: an aware timestamp names an instant and a naive one names a calendar reading, and no rule relates them without assuming the writer's timezone, so aware ↔ naive stays a type-only edit; date ↔ aware timestamp fails the same way, midnight having no timezone to happen in; and a string with an offset designator never matches a naive column, nor one without an offset an aware column, the profile divide drawing the same line for parsed values.

# Scope

## What changes

- `src/compare.rs`: the promoted kinds and domains, `CanonicalValue::Nanos` and `CanonicalValue::Rational`, their canonicalizations, and the new `stable_hash` tags.
- `src/input.rs`, `src/model.rs`: `NormalizedType::{Timestamp, Date, Decimal}` classified ahead of the opaque probe.
- `test-support`: the five new annotations.
- `Cargo.toml`: `arrow-buffer` if `i256` needs a direct dependency.
- `design.md`, `README.md`, `demo/README.md`, `examples/generate_demo.rs`, and the test suites.

## What stays and why

- **Everything above the comparison.** Keys, guessing, rename and swap inference, cells, ordering, change mass, summarization, and reconsideration are generic over plans and canonical values; promotion widens which pairs have plans and changes no consuming code, and the fall-out item verifies that claim rather than acting on it.
- **The incomparable-pair machinery.** Pairs outside the decided matrix still keep identity and lose the value story, exactly as the opaque step built: type-only `col_edit()`, `incompatible_types` for a declared key, no inference proposals. Promotion relaxes entries in the matrix, not the machinery around it.
- **The existing matrix and the opaque regime for unlisted families.** No normalized pair's rule changes; durations, times, intervals, binary, lists, structs, and dictionary-encoded values keep identical-type-only comparison by canonical bytes.
- **Swap inference's identical-type crossings.** A swap overrides an established identity and answers to a higher bar than a rename; that reasoning is unchanged by more pairs becoming comparable.
- **Null and `NaN` rules.** Nulls canonicalize to `Null` before any promoted encoding, and `NaN` semantics live in the `Double` canonicalization the `DecimalDouble` domain reuses, so nothing new is special-cased.

## Explicitly deferred

- **Aware ↔ naive timestamps and date ↔ aware timestamp.** Refused, not deferred by accident: no rule is defensible without assuming a timezone the data does not state. If a future step wants an assumption, it should be a declared hint, not a default.
- **Local times, durations, and intervals across units.** They keep the opaque step's identical-type-only comparison — still admitted, still comparable within one type — which the owner has judged sufficient to close [#2](https://github.com/hadley/data-diff/issues/2). Recorded in `design.md` as a decision, with the `Nanos` machinery making later promotion cheap if a need ever arises.
- **Dictionary-wrapped promoted types.** `Dictionary(_, Timestamp(...))` and kin stay opaque, identical-type-only; hydrating them into their family's domain is mechanical but rides better on a demonstrated need.

# Design

## Exactness by widening

The queue requires overflow-checked unit conversion, and the cleanest checked arithmetic is arithmetic that cannot overflow. Every temporal value in any Arrow unit fits in `i128` nanoseconds with room to spare, and every decimal mantissa and reduced double fits in `i256`, so both canonical forms are computed by total functions and the exactness argument is by construction rather than by audit of checked call sites. The cost is a wider canonical value for these domains, which the existing `Vec<u8>`-carrying variants already dwarf.

## One canonical form per domain, as ever

The matrix's existing discipline is that each domain chooses one canonicalization and equality is equality of canonical values, which is what lets hashing, frequency counts, keys, and inference work unmodified. The promoted domains follow it exactly: `Nanos` for the temporal domains, `Rational` for the decimal ones, with the mixed domains (`DateTimestamp`, `DecimalInt`, `DecimalDouble`) mapping both sides into one space the way `IntDouble` and the string domains always have. The non-composition of equality across type triangles is already a recorded, pinned property of the matrix; the promoted domains add triangles of the same kind — a date equals a naive midnight timestamp and a `Date64` equals its `Date32`, each pair under its own domain — and the same reasoning covers them: no stage chains comparisons across pairs.

## The midnight rule

Date ↔ naive timestamp is the one listed pair where "the same value" needs a convention, and the queue names the choice: midnight or refusal. Midnight is chosen because a date column retyped to a timestamp lands at exact midnight in every common writer, so the rule recovers the retype the way the 0/1 rule recovers boolean retypes; and it is strict — one nanosecond past midnight is unequal — so it claims nothing the bytes do not show. Refusal was rejected because it treats the commonest date retype worse than every other family's, and the pairing is with the *naive* timestamp only, where midnight is a calendar fact rather than a timezone assumption.

## One profile per partner category

ISO 8601 is a family of formats, and "parse ISO 8601" underdetermines a comparison; what the matrix needs is one decided spelling per domain, which is how the numeric string domains already work — `bool::from_str` for booleans, the exact integral parser for integers. The three profiles are selected by the partner column's category: calendar date against a date, unzoned date-time against a naive timestamp, offset instant against an aware one. Selection by partner keeps the aware/naive line honest in string form — an offset is required exactly where the column names instants and refused exactly where it does not — and it means a date-only string beside a timestamp column is a mismatch rather than an implicit midnight, midnight being the `DateTimestamp` domain's decided rule for *typed* dates, not a reading of absent text. The resulting triangles ("2026-08-03" equals the date, the date equals its midnight naive timestamp, the string does not equal that timestamp) are the same non-composition the matrix already records and pins; no stage chains comparisons across pairs. Strictness follows the existing parsers' discipline — locale-independent, case-sensitive, untrimmed, exact — so the profile is checkable in the head: extended format, uppercase designators, four digits of year, a real calendar date, at most nine fractional digits. The decimal string domain is the one that needs no choosing at all: the exact numeric grammar is already the matrix's one spelling of a number, and reading it to a rational rather than an `i64` is the same parser held to the same exactness with a wider target.

# Definition of done

This step is complete when:

- every pair in the Goal table compares by its decided rule, exactly, with no comparison passing through lossy conversion and no conversion able to overflow;
- ISO 8601 strings parse against dates and both timestamp categories under their selected profiles, and decimal strings under the exact numeric grammar, strictly, with a parse failure a mismatch and never an error;
- every named refusal remains a planless pair with the opaque step's behavior — identity kept, values uncompared, keys rejected as `incompatible_types` — and is pinned by a test;
- a cross-unit timestamp column serves as a declared or guessed key, is recovered by rename inference, and reports its cells, demonstrating the promotion falls through every stage;
- `NormalizedType` and the design's tables describe the new regime in present tense, with each refusal recorded with its reasoning;
- the demo shows a promoted retype and the surviving incomparable pair, held to real output; `plan-next.md` stays as the owner trimmed it, carrying only benchmarking; and
- the full test suite, strict Clippy, formatting, and diff checks pass across the workspace.
