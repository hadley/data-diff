# Goal

Reorganize the UI from "schema panel on top, three tabbed views below" into a master-detail layout: a narrow sidebar listing every diff component with its count, and a full-size main panel showing the selected component's table under a common toolbar. The table is the star — it fills the panel and scrolls freely in both directions with keys and column names always pinned — and the sidebar gives one-click access to every category of change at the same granularity the CLI reports, including individual edited-row groups.

# Scope

`ui/src/App.tsx` (layout), a new sidebar component, the four existing views (SchemaPanel, ColumnView, RowView, CellView — rehomed and de-paginated, contents unchanged), `PagedTable.tsx` (becomes the windowed, dual-pinned table), `style.css` (layout and sticky styles), `ui/server` (the edited-group filter parameter only), `ui-design.md` (organization wording), and the frontend and server tests. Deferred: the change-summary block on the schema view (layout must leave room, nothing more); cell view's column/row filters and drill-down from other views (ui-design.md mentions them; they are their own step); any change to what the views show or to the reconciliation model — this step is pure reorganization plus the one server filter.

# Design

The central invariants are untouched: no reconciliation change, no new inferred anything, and the cell view remains exactly `Diff::cells`. The design's "everything is paginated and lazily loaded" principle is preserved — virtualization changes only the frontend's fetching rhythm (pages appended on scroll instead of paged through), not the server's page-sized contract or the rule that no view holds more than a window of values. Hiding empty categories in the sidebar formalizes what `RowView`'s sections already do (`if (count === 0) return null`). The one genuinely new behavior is the edited-group filter, and it is a selection over the existing grouping, not a new grouping: the sidebar's sub-entries and the filtered view both come from the same `/api/row-view?kind=edited` machinery, so counts cannot disagree.

# Definition of done

The UI presents the sidebar + main-panel layout with counts, hidden empty categories, and per-group edited sub-entries; every table view fills its panel, scrolls in both directions with keys and headers pinned, and loads rows continuously on scroll with no pager; the toolbar shows each active view's existing controls; the schema view is the opening view; the edited-group filter is covered by server tests; `ui-design.md` matches the shipped organization; and the full acceptance pass is clean with byte-identical repeated runs.
