# Todo

- [x] **Replace the unweighted cover with a weighted one.** In `src/summary.rs`, swap the Hopcroft–Karp + König extraction for a min s–t cut (weighted König): source→row edges carry the row weight, column→sink edges carry the column weight, cell edges carry infinite capacity. Dinic's algorithm with adjacency in ascending vertex order keeps it deterministic; the cover is recovered from the reachable set after the final BFS, same shape as today (selected rows = unreachable left, selected columns = reachable right).
- [x] **Define the MDL weights in fixed-precision integer arithmetic.** `w_row = log2(R) + log2(C choose c)` and `w_col = log2(C) + log2(R choose k)`, where R/C are the matched-row and identified-column counts of the whole comparison (not the component), and c/k are the vertex's changed-cell counts. Compute in f64, round to centi-bits (`i64`), and document that choice in the module docs: weights are irrational, so byte-identical output requires fixed precision, and centi-bits are far finer than any realistic gap between covers. Ties after rounding break by the existing deterministic traversal order.

# Goal

Make "parsimonious" mean minimum description length instead of fewest events, per the analysis in issue #38: weight each candidate `row_edit`/`col_edit` by the bits needed to state it (`log2(R) + log2(C choose c)` / `log2(C) + log2(R choose k)`) and solve the weighted minimum vertex cover exactly. Then let `row_edit()` carry the column set it pays for, so identical rows collapse into one rectangle-stating line in both the text output and the UI row view.

# Scope

`src/summary.rs` (solver, weights, fallback), `src/model.rs` (`RowEdit.columns`), `src/human.rs` (printing, grouping), design.md grammar and wording, the demo transcripts, and the UI (`ui/server/src/commands.rs` grouping, DTOs and snapshots, `RowView.tsx`, opening-view tests). Deferred: any change to hint semantics (row edits stay non-hints), exposing weights in the output, tuning or configuring the weight function, and touching the cell-level diff (untouched by design).

# Design

The central invariants hold: reconciliation is unchanged, every printed event is still backed by underlying changed cells, and `Diff::cells` remains the complete cell-level diff. What changes is only how the summary covers those cells. The weights are a deliberate per-row upper bound on description length, not exact MDL: the solver charges `log2(C choose c)` for every selected row even though grouping prints a shared `columns:` list once per block, and a doubly-covered cell is specified twice. The claim is "minimum-weight cover under these weights", and that is what `optimal` and design.md will say — the per-row binomial term is still what makes the printed `columns:` field affordable, which is why the two reinforce each other without being the same count. On the issue's demo pair (R = 9,980, C = 10) the weights give, with no tuning: the every-20th-row `price` edit stays a `col_edit` (≈2,856 bits vs ≈8,283 as rows) and the 50×5 rectangle flips to rows (≈1,065 bits vs ≈2,287 as columns).

# Definition of done

The demo pair from issue #38 summarizes as one `col_edit(price, ...)` plus a single grouped `row_edit([2001, 2002, ..., 2050], columns: [r1, r2, r3, r4, r5])` line; the solver is exact (weighted) at or below the cell cap and the fallback compares sides by weight above it; output is byte-identical across repeated runs; design.md, demo/README.md, and the UI reflect the new rule; and the full acceptance pass is clean.
